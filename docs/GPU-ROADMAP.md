# GPU 路线：与 CPU 第一版分开

状态：计划，尚未安装训练环境、下载训练模型或启动训练。当前第一版不需要 GPU，也不需要 Dify 服务器。

## 启动条件

先完成公开数据的 CPU 基线、错误分类和冻结划分。只有知道瓶颈，才能决定训练什么。RTX 4060 笔记本 8GB 是可尝试小模型实验的设备条件，不是任意模型都能训练的保证。

## 两条候选，只根据错误选择一条

1. **OCR 文字基本正确，字段选错：**考虑版面感知的字段分类模型，输入文字、位置与图片；训练目标是字段标签。必须解决实体标签到 OCR token 的对齐，处理重复金额、长序列截断和未知字段，不可简单按字符串相等生成所有训练标签。
2. **OCR 文字本身大量错误：**先按错误字、旋转、模糊和票据模板分析，再考虑 OCR 识别模型的小规模适配。不要同时改检测、识别、抽取，无法定位收益。

多模态生成或小模型 LoRA 作为额外候选，需要检查模型许可证、字段结构约束、图像 token 成本、推理延迟，以及生成内容能否回指证据。LlamaFactory 仅在选定模型和训练任务确实被它支持时再接入，不预先安装。

## 实施顺序与验收

1. 新建独立训练目录/环境，记录 PyTorch、CUDA、驱动和模型版本，不改当前 CPU .venv。
2. 只用少量样本跑一个前向和反向，batch=1 起步；测真实峰值显存、耗时。超显存优先减少分辨率/序列长度或模型规模，再评估混合精度、梯度累积、检查点；不能把梯度累积说成减少单样本内存。
3. 固定训练/开发/测试划分与随机种子；记录模型预训练数据可能带来的基准污染。
4. 保存可复用数据转换、训练、推理、评估文件；训练日志与配置随报告留存。
5. 与规则基线在同一冻结样本比较字段准确率、整单准确率、错误类别、延迟与资源。
6. 没有可靠收益就保留基线，记录失败原因；有收益后才接入 extraction 的模型适配层，保持 API 与审计结构不变。

最终具体模型、依赖版本和显存参数要在这一阶段开始时重新核验官方文档并实测，本文件不把未经验证的组合写成能运行的教程。
